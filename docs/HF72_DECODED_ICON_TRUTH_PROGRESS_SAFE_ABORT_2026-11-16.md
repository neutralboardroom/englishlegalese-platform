## Material HF72 improvements
1. **Actual decoded PNG pixels on supported browsers.** Following the existing bounded streaming, full PNG chunk CRC and structural checks, the optional public device diagnostic uses `createImageBitmap(new Blob(...))` on the 192px and 512px public icon files. It verifies the decoded bitmap dimensions, closes bitmap resources in `finally`, and treats decoder errors or inconsistent dimensions as failure rather than declaring an unusable icon valid. Older environments without the decoder retain the previous CRC/structure-only evidence; no guarantee of full pixel decode is claimed there.
2. **Progressive, accessible feedback.** All seven existing diagnostic messages append to the existing semantic results list as each check finishes. A status line announces progress. Previously a slow browser could display a blank list until every public download finished. No design, homepage, or consent behavior changes.
3. **Unambiguous manifest icon mappings.** Each required icon size must have exactly one entry pointing to the original same-origin image/png icon path. Null or duplicate mappings fail closed; required identity, scope, start URL, display and other HF65–HF71 validation remain in effect.
4. **Reject bad headers without retaining response readers.** Invalid type/status/redirect/advertised content length attempts best-effort `AbortController.abort()`; successful requests still use `credentials:'omit'`, `cache:'no-store'`, `redirect:'error'`, the 1MiB stream cap and prior timeout safeguards.
5. **Failure-safe control state.** A `finally` clause always re-enables the user-initiated check button after unexpected exceptions. No diagnostic is initiated before the visitor clicks, and no authenticated/private/account/class/teacher/owner/employer API route is requested.
