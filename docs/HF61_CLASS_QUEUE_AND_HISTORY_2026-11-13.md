## Multi-workstream HF61 changes actually coded
1. **Review-first, upcoming-first class ordering** — the authenticated `GET /api/v2150/private-energy/sessions` puts pending student changes before upcoming records and old history. Uses `LIMIT 51` to disclose `partial: true` when only 50 of more records are shown. Never equate returned class records with distinct current students, attendance, paid enrollments or complete counts.
2. **Independent bounded, authenticated historical pagination** — `GET /api/v2150/private-energy/sessions/history?offset=N` loads only owned historical/expired classes, 25 per page and at most 26 returned internally for a true more-pages indicator. It uses the real account's existing revocable session, status and ownership, refuses malformed/excessive offsets and never reveals a past Meet link to student or teacher.
3. **Real teacher-only pending decision queue** — `GET /api/v2150/private-energy/review-queue` separately exposes up to the first 50 assigned pending requests, with a `partial` warning if there are more. The queue is identity-minimized: session id, lesson, requested kind, proposed date and timestamps, **no student email, Meet URL or confidential contract text**. Not a claim that any Google Calendar was scanned.
4. **Classroom UI** — clearly warns that the first 50 prioritized class records are not necessarily the full list, provides an accessible 25-per-page history loader that deduplicates records, and adds a teacher-only review overview with links to the existing authenticated class review controls. Never silently treat a historical learner as active.
5. **Atomic database safeguards** — student change request write now rechecks BOTH pending and coordination-required states at the write itself; attaching or generating Meet links requires no unresolved change request in both the preflight and database conditional update; marking the class completed refuses unresolved changes in both preflight and database write. No review decision automatically changes calendar events, bills/refunds, credits or emails.
6. **Cross-role synthetic integration and browser regressions** — new `scripts/verify-hf61-queue.js` and `tests/hf61-private-queue.spec.js` check explicit role/record scoping, queue truncation, paged historical records, omitted meeting links, race controls, no provider calls, UI partial warnings and teacher-only navigation. Wired into the mandatory `npm run check` and Playwright project.
