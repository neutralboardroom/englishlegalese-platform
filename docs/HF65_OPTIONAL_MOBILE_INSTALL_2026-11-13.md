## New HF65 mobile phone application — implemented in source

- **Installable Progressive Web App (PWA), not a native APK or App Store .ipa:** `manifest.webmanifest` has EnglishLegalese identity, start URL `/`, site-wide scope, `standalone` display, official existing brand colors, and 192px/512px validated PNG icons generated from the exact preserved `assets/favicon.svg` artwork. The original logo, teacher photo and favicon files are NOT replaced.
- **Real optional installation choice:** `/learn/install/` explains Android/Chromium `beforeinstallprompt` (only triggered when the visitor presses the visible install button), iPhone/iPad Safari Share > Add to Home Screen, and other-browser fallback. No call to `prompt()` on load, no forced download or silent install, no false claim of an App Store/Play listing. People can use the regular website with no app.
- **Discoverability:** a visible optional app link is added to the homepage footer; a shortcut is added to the Account landing page. The original homepage hero/photograph/pricing and course lessons remain intact, not reconstructed. Both homepage and Account link to `manifest.webmanifest`; Apple-touch icon is exposed.
- **Privacy-preserving standalone use:** `sw.js` is registered only when the visitor opens the dedicated install page. It captures only same-origin GET navigations, attempts network-only first (no stored webpages), and if offline displays a generic pre-cached `/learn/install/offline.html` notice. It specifically avoids intercepting private account/teacher/employer/owner pages, all API endpoints, and all other non-navigation requests. It never stores token, password, Google Meet URL, messages, student work, uploaded documents, learning history, financial data or provider responses. The cache contains exactly the static offline page and no student content.
- **Correct server serving:** `server.js` explicitly returns `/manifest.webmanifest` as `application/manifest+json`, `/sw.js` as JavaScript with `Service-Worker-Allowed: /` and no-cache/revalidate headers. These routes precede Express static and touch no authentication APIs.
- **App integrity and usability:** the install page is accessible, responsive, supports reduced dependency (plain HTML/JS), has manual iOS steps, no background monitoring, generic uninstall instructions and clear online-only requirements for actual classes and saved work. Installed app uses SAME Legal and Business English website and account system; no duplicate student database.
- **Automated protection:** `scripts/verify-hf65-mobile-install.js` validates actual binary PNG dimensions and manifest wiring, server behavior, consent-only prompt, privacy/static caching boundaries and originality of the old favicon. `tests/hf65-mobile-app.spec.js` runs Android-like mobile Chromium, desktop Chromium, tablet Chromium and iPad/WebKit browser qualification including manifest/icon routes, no unsolicited POST, synthetic browser-install event requiring a real user click, and actual public offline fallback in Chromium after service worker control. The complete existing HF1–HF64 suites remain enabled and unmodified.

## Website and native mobile distinction

- **Delivered now in a GitHub development candidate:** optional installable browser-based app, Android/browser install prompt, iOS home-screen path, network-first site, generic offline state. Deployment is required before real customers can install it.
- **Not delivered now:** signed Android APK or Google Play Store package, signed iOS IPA or Apple App Store listing, app-store review, platform push notifications, fully offline course materials, private data sync without connectivity, direct automatic download or independent native apps. Such features require app store developer identities, release signing, distribution decisions, policies and separate QA.
- Browser install prompts, Safari menu names and support vary by device and operating system. Tests can verify implementation and browser behavior in a test environment but **cannot confirm installation on the user's actual phone** without a real-device acceptance test.
