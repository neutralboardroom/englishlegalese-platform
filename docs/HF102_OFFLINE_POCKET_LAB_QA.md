# HF102 — offline-only single-file adult English practice

New public, explicitly downloadable one-file HTML teaching handout for low-connectivity adult learners, distinct from the existing service-worker/PWA account model. Covers three authored fictional Legal English and three Business English professional exchanges from the original HF93 curriculum (contract comment deadline, NDA scope, client format, Wednesday draft versus Friday review, explicit task ownership, higher orders versus uncertain revenue). Each contains actual two-speaker dialogue, a source-accurate three-option comprehension question, an explanation, a second three-option clarification question, an optional private written confirmation draft, self-review guide, and an authored short professional note. Complete exercises operate using inline CSS/JS/content with no external resources or fetches.

## Offline limitations and privacy

A learner must download/save the HTML file while connected and open the saved file. This is **not** a promise the website or PWA is cached offline, and does not permit offline access to accounts, paid lessons, private records, enrollment, certificates, voice, teacher or payments. No localStorage/sessionStorage/indexedDB/cookies/service workers; no microphone, voice data, analytics, AI, network APIs, external images/fonts or styles. `Content-Security-Policy` forbids connect/image/form sources, and all content, model replies and questions are embedded inline. Optional writing is transient and cleared by Clear, next case, subject change, pagehide and unload. No automatic evaluation of writing/speaking (multiple-choice comprehension checks are limited to the authored scenario). Never enter private employer/client information. Adult examples are fictional, not legal or financial advice.

## Verification

Source verifier checks data, dependencies, privacy, CSP, no external assets, continuity and lesson files. Local Chromium administrator blocked direct `file://` navigation. Instead, the unmodified complete standalone HTML content ran with its inline JavaScript under Chromium `page.set_content` across 320, 390, 768 and 1280 viewports, all six cases. This does not prove that the local file protocol worked. It checks both right and wrong choices, stage gates, note model, draft erasure, zero network requests/exceptions and no horizontal overflow. GitHub Playwright addition covers file protocol scenarios plus hosted static route; independent Chromium and isolated Safari WebKit GitHub CI must still pass on exact SHA. Physical device Safari/Android local-file handling requires real device review, not simulated assertions.
