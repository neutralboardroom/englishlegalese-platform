## Cumulative actual HF66 source improvements
1. **Visitor-initiated app updates, no surprise classroom reload:** The public install page offers separate buttons to *Check for app updates* and *Apply update and reload this page*. The existing service worker stays active until the visitor explicitly confirms a waiting update. Only a matching `ENGLISHLEGALESE_APPLY_UPDATE` message from an existing browser client invokes `skipWaiting`. Only the public installation page reloads, and only when its own apply button was clicked; never reload a live class or silently submit unfinished writing. Existing one-click Android installation and iOS Safari Add to Home Screen directions are preserved.
2. **Strict safe offline boundary:** The service worker caches one static generic offline HTML page and nothing else; it uses network-first, no-store public navigations. A narrow explicit allowlist permits the generic fallback only on the homepage, install page, Start, Courses, Legal English, Business English, public resources and Pricing. All other future routes, private student/teacher/employer/owner pages, meeting joins, billing and API requests are outside worker interception and remain network-only. No private data, accounts, Meet URLs, AI answers, contract files, user analytics, or auth tokens are persisted.
3. **Meaningful mobile app navigation:** The installed-app manifest retains the same site-wide shared course/account system and adds platform shortcuts to *Legal English*, *Business English*, and *My account* (authentication still required for Account). No second database or unauthorized external API.
4. **Practical regional onboarding:** The optional install page has readable simple Android/Safari installation instructions in English plus labelled Thai, Vietnamese and simplified Chinese disclosures. These texts do not promise fully translated classes or guaranteed Chinese video-provider access.
5. **Truthful device/update status:** Accessible live status reports a device-provided connectivity indicator, not proven internet availability; update availability is checked explicitly. The interface separates the installed-app indicator from the update mechanism so installed users can still check.
6. **Substantive tests:** `scripts/verify-hf66-mobile-lifecycle.js` exercises an actual synthetic service-worker VM: public-only offline fallback, no API/private route interception, no cache writes beyond the generic page, old worker cleanup without deleting unrelated caches, no automatic `skipWaiting`, and explicit client-initiated activation; validates full Legal + Business app shortcuts and Thai/VI/ZH sections. `tests/hf66-mobile-lifecycle.spec.js` verifies the update controls, locale content, unchanged full navigation, manifest and public offline behavior across the existing desktop/mobile Chromium and tablet WebKit matrix. Both are **added** to inherited mandatory `npm run check`; older tests remain enabled.
